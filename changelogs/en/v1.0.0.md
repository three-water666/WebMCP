# v1.0.0 (2026-08-29)

## Features

- Added workspace file attachments for browser-delivered tool results. `attach_file`
  now supports validated images, PDFs, and UTF-8 TXT files up to 20 MB, preserves
  request mapping across result batches, pastes files before result text, and reports
  partial delivery failures per request. (#68)
- Added risk-aware command approvals. Shell commands are classified as allowed,
  confirmable, or blocked, with single-use preflight tokens, separate approval scopes
  for shell semantics, and hardened path/option parsing for POSIX and PowerShell. (#67)
- Added ChatGPT response-stream tool capture. The browser bridge can extract completed
  tool calls directly from response streams, execute network-owned turns with DOM
  fallback and deduplication, and show queued, approval, execution, and delivery state
  in the shared activity panel. (#66)

## Improvements

- Tool activity now also groups DOM-captured calls by assistant message and resets
  capture state cleanly across site or configuration lifecycles.
- Interactive browser QA now requires explicit user authorization, isolates extension
  builds per run, validates local browser and VS Code paths with actionable failures,
  and defaults to DeepSeek while preserving supported site selection.

## Engineering

- Added agent-led, scenario-driven interactive QA with isolated browser and VS Code
  sessions, Playwright inspection, lifecycle checks, run-scoped screenshots, and
  agent-owned QA verdicts backed by deterministic evidence. (#65)
- Added a deterministic real-task evaluation harness with scenario fixtures, hidden
  graders, DeepSeek live-site evaluation, persistent-profile setup controls, traces,
  failure attribution, and protocol diagnostics. (#64)
- Expanded Extension Host integration coverage and release CI checks so missing compiled
  host tests fail explicitly and VS Code test runtimes can be reused across jobs.
